# Dependency overrides for the vLLM install in install-vllm-tt.sh.
#
# ttnn pins numpy>=1.24.4,<2, but vLLM's requirements/common.txt asks for
# opencv-python-headless>=4.13.0, which requires numpy>=2.
# Without overrides, the install rewrites numpy with the newer version.
#
# numpy<2 wins: it is fixed by the tt-metal env this plugin runs inside
# (tt-metal pyproject.toml and tt_metal/python_env/requirements-dev.txt) and
# cannot be moved from here. opencv is reached only by vLLM's lazy video-IO
# path (vllm/multimodal/video.py), which no TT-registered model uses, so 4.11 —
# the last release without a numpy 2 floor — is safe.
#
# Revisit when bumping the pinned vLLM version (upstream may relax the opencv
# floor again), or if a TT-supported model gains video input, or if tt-metal
# bumps the numpy requirement
# (https://github.com/tenstorrent/tt-metal/issues/30193).
opencv-python-headless==4.11.0.86
numpy>=1.24.4,<2

# Retarget this range when the pinned vLLM moves; do not just delete it: it is where
# to cap transformers if a release breaks the tt-metal env. --override replaces a
# requirement instead of intersecting it, so this line is the whole transformers
# constraint of the install. It restates vLLM 0.32.0's own range. tt-metal pins
# transformers 5.12.1 (tt_metal/python_env/requirements-dev.txt), but common.txt
# requires tokenizers>=0.23.2 and every transformers release below 5.16.0 caps
# tokenizers at 0.23.0, so the install upgrades transformers in the tt-metal env to
# a release tt-metal does not validate. transformers 5.15.0 and later raise
# AmbiguousGlobalPerLayerAttributeError when code reads head_dim or
# num_key_value_heads off a Gemma 4 or DiffusionGemma text config instead of
# text_config.per_layer_config[i]; tt-metal's Gemma 4 and DiffusionGemma model code
# must read them per layer before those models can run on this install.
transformers>=5.16.1,<5.20.0
